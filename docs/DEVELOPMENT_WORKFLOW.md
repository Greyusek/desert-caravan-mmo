# Быстрый процесс разработки до MVP

Этот режим действует до отдельного решения изменить процесс. Его цель — убрать повторную ручную проверку обычных небольших PR, сохранив автоматический барьер от заведомо сломанной сборки.

## Обычный цикл

1. Codex берёт только одну задачу из `TODO.md`, создаёт отдельную ветку и PR.
2. Codex выполняет `npm ci`, `npm run verify:local` и `git diff --check` до публикации.
3. GitHub Actions выполняет чистую установку, одну TypeScript-сборку и все тесты.
4. Ручной review обычного небольшого PR до MVP пропускается. Merge выполняется только после зелёного `CI / verify`.
5. После merge локальная копия принимается одной командой или двойным щелчком по командному файлу.

Изменения GitHub workflow/permissions, зависимостей, секретов и авторизации, постоянного хранилища/миграций, удаление данных и большие сквозные рефакторинги требуют ручной остановки и review.

## Автономная серия и ограничение Work

При выполнении нескольких задач подряд краткое оперативное состояние хранится
в [`WORK_HANDOFF.md`](WORK_HANDOFF.md). После каждой законченной логической
задачи сначала проходят проверки и создаётся стабильный commit, затем
обновляются `TODO.md`, `ROADMAP.md` и handoff. Старая оперативная информация в
handoff заменяется актуальной, а полная история остаётся в Git.

Если оставшегося ресурса может не хватить на безопасное завершение следующей
задачи, новая задача не начинается. Текущая работа доводится до ближайшей
стабильной точки, handoff обновляется, и серия останавливается с причиной
`RESOURCE LIMIT CHECKPOINT`.

## Локальная приёмка на Windows 11

После merge PR, который впервые добавляет эту автоматизацию, один раз получите сам скрипт вручную:

```bash
cd /d/dev/newWorld
git switch main
git pull --ff-only origin main
npm run accept:main
```

Начиная со следующего PR достаточно одной команды — она сама обновит `main`:

Из Git Bash:

```bash
cd /d/dev/newWorld
npm run accept:main
```

Из PowerShell, где может блокироваться `npm.ps1`:

```powershell
cd D:\dev\newWorld
npm.cmd run accept:main
```

Для запуска двойным щелчком откройте `scripts\accept-main.cmd`.

Скрипт безопасно останавливается при незакоммиченных файлах, переключается на `main`, выполняет только fast-forward pull, проверяет точное совпадение с `origin/main`, устанавливает lockfile-зависимости, один раз собирает TypeScript, запускает все тесты и demo, затем снова проверяет чистоту дерева.

Логи создаются рядом с репозиторием. Для `D:\dev\newWorld` это каталог `D:\dev\newWorld-logs`:

- `accept_YYYYMMDD_HHMMSS_summary.txt` — короткий итог, который нужно присылать после успеха;
- `accept_YYYYMMDD_HHMMSS.log` — полный вывод, который нужен только при ошибке или по запросу.

## Откат

Если проблема обнаружена после merge, создайте обратный коммит кнопкой **Revert** в GitHub или командой `git revert <merge-commit>` в отдельной ветке и снова проведите его через CI. Не используйте `reset --hard`, force-push или переписывание истории `main`.
