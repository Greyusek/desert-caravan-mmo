# Ручная проверка Checkpoint 76 — PLAYER-PREP-001

Проверка выполняется после merge PR в `main`. Переключаться на служебную ветку
не нужно. Debug UI для этой проверки тоже не требуется.

## 1. Обновить локальный проект

Откройте **Git Bash** и выполните команды по очереди:

```bash
cd /d/dev/newWorld
git switch main
git pull --ff-only origin main
npm ci
```

Если проект находится в другой папке, замените только `/d/dev/newWorld` на свой
путь. После `git switch main` терминал должен показывать ветку `(main)`.

## 2. Запустить Player UI

В том же окне Git Bash выполните:

```bash
npm run player-ui
```

Не закрывайте терминал. Дождитесь строки:

```text
Desert Caravan MMO Player UI: http://127.0.0.1:4174
```

Откройте в браузере <http://127.0.0.1:4174>. Если страница уже была открыта,
нажмите `Ctrl+F5`.

## 3. Тест 1 — исходный состав

1. Дождитесь исчезновения надписи «Подготавливаем журнал каравана…».
2. Нажмите слева **Караван**.
3. В верхней сводке проверьте: `2` бойца, `100` еды, `100` воды и груз
   `10,2 / 20 ед.`.
4. Справа должны быть карточки **Страж** и **Застрельщик**. У них должны быть
   здоровье, ход, дальность и урон.
5. В разделе багажа должны быть **Руда — 5 ед.** и
   **Лекарства — 2 ед.**, обе с прочностью `6 / 6`.

Ожидаемый результат: экран показывает фактический состав и груз каравана, без
seed, координат мира, монстра и DEV-кнопок.

## 4. Тест 2 — фиксированное построение

1. В блоке «Тактическое построение» найдите отметку **Принято ядром**.
2. На поле должны быть отдельные фишки Стража, Застрельщика, Руды и Лекарств.
3. Остальные клетки должны оставаться свободными.
4. На экране не должно быть кнопки перемещения или перестроения.

Ожидаемый результат: построение читается, но не редактируется. Это специально:
текущее тактическое ядро пока не поддерживает отдельную проверенную команду
предбоевого перестроения.

## 5. Тест 3 — единый груз с городским рынком

1. Нажмите слева **Город**.
2. В строке **Еда** нажмите **Купить** один раз.
3. Вернитесь в раздел **Караван**.
4. Проверьте, что общий груз стал `11,2 / 20 ед.`, в багаже появилась
   **Еда — 1 ед.**, а на поле появилась ещё одна багажная фишка.

Ожидаемый результат: городской рынок и подготовка показывают один и тот же
физический груз, без перезагрузки страницы.

## 6. Тест 4 — сохранение маршрута и блокировка в пути

1. Нажмите слева **Карта**.
2. Выберите **North Camp** и нажмите **Проложить маршрут**.
3. До отправления снова откройте **Караван**: экран должен оставаться доступен,
   а состав и груз — без изменений.
4. Вернитесь на **Карту** и нажмите **Отправить караван**.
5. Проверьте, что разделы **Город** и **Караван** стали недоступными.

Ожидаемый результат: подготовка доступна в городе и после планирования маршрута,
но закрывается после фактического выхода каравана.

## 7. Тест 5 — отсутствие ошибок запуска

1. Нажмите `F12` и откройте вкладку **Console / Консоль**.
2. Обновите страницу сочетанием `Ctrl+F5`.
3. Снова откройте раздел **Караван**.

Ожидаемый результат: нет красных ошибок `Player UI module failed to load`,
`missing element` или ошибок загрузки `/api/player-session`.

## 8. Завершение

Вернитесь в Git Bash и остановите сервер сочетанием `Ctrl+C`.

Если все пять тестов прошли, достаточно написать: **«Checkpoint 76 принят»**.
При ошибке приложите скриншот страницы, текст из консоли браузера и вывод из
Git Bash.
